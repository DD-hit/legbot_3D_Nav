# 迹航 · 导航工作台

此页面控制 `building2_9` 地图上的 `ROS 2 Humble` 仿真。单点和多点共享一个任务接口。定位成功后机器狗待命，由用户选择开始导航。

## 楼层名称、常用点位与巡检路线

- 在地图左上角选定楼层，点“改名”。新的名称会同步显示在楼层菜单、楼梯、定位和任务明细中。
- 新建单点或多点任务，在地图拖动设置目标位姿，点“保存点位”或“保存路线”并命名。也可以从上次任务的“保存到资料库”保存全部停靠点。
- 页首“点位与路线”按类型列出已保存的记录。“使用”载入草稿；编辑多点任务时，“添加”把记录追加到末尾。“编辑”可改名、重新选点或调整站序，“删除”需确认。点击“开始导航”才会下发任务。
- 路线保存各站的楼层、位置、朝向及顺序。执行时规划器根据当前机器人位置重新规划各段路径。记录按地图保存在当前浏览器的 `IndexedDB`（索引数据库）中，刷新或重启浏览器后仍可使用。清除该站点数据会删除记录。换浏览器或改变访问端口会使用独立的资料库。

## 启动与连接

在 `rl@100.73.76.90` 的工作区运行以下命令。首次打开时等待机器人站稳。

```bash
cd /home/rl/workspace/legbot_3D_Nav
source tools/env_humble.sh
ros2 launch legbot_bringup pct_cross_floor_demo.launch.py \
  navigation_source:=map_localized web_console:=true gui:=false rviz:=false
```

在自己的电脑建立 SSH 端口转发，然后打开 <http://127.0.0.1:8765>。如果本地端口已用于其他服务，可把 `-L` 后第一个端口改成 `8766` 并打开对应地址。服务仅监听服务器的回环地址。

```bash
ssh -NT -L 127.0.0.1:8765:127.0.0.1:8765 rl@100.73.76.90
```

## 定位和选点

1. 选择机器狗所在楼层，点“拖动给定初始位姿”。在地图上按住机身位置，向狗头方向拖动后松开。默认仿真出生在入口层，约 `(-5.5, 6.0) m`，狗头朝地图右方。指针坐标显示在地图下方。
2. 提交初值后机身箭头消失。网页模式允许在初值周围 `1 m`、偏航 `±30°` 内搜索，通过独立点云复核并收到有效位姿后才显示绿色机身箭头。匹配失败后可以调整楼层、位置或朝向重新提交。
3. 地图默认用于浏览。新建任务后，在目标位置按下，沿期望的狗头方向拖动后松开。单点任务再次拖动会替换终点，多点任务每次拖动会追加一个停靠位姿，可跨层、前移、后移、删除。点“取消编辑”放弃草稿并返回浏览。
4. 点“开始导航”。橙线表示当前段的全局路线。后端核对当前目标的停车回执后，从机器狗的最新估计位置规划下一段。最后一站确认停车后任务才完成。
5. 规划或行走中可点页首“取消任务并停车”。系统撤销运动许可，待连续新鲜里程计确认机身站稳后显示“任务已取消”。取消或失败后点“编辑剩余点”可重新打开草稿。里程计中断时，停车确认要等待观测恢复。

网页默认显示从 `building2_9.pcd` 分层提取的墙体及竖向结构。勾选“显示规划限制”可叠加 `PCT`（点云分层规划）的受限栅格。两个图层使用相同的坐标和分辨率。更换点云或规划地图后，运行 `python3 tools/build_floor_display.py` 并重新构建 `legbot_bringup`。

本楼宇配置了 `0、1.5、3、4.5、6 m` 五个显示高度带。Web 仿真与网页选点共同使用 `building2_9_entry.pickle`；原版 `building2_9.pickle` 保留用于对照。规划器与选点接口都要求有效楼面和 `0 < cost <= 20`。指针和待执行列表显示落点的实际楼面高度。连通性在下发任务后由全局规划逐段判断。规划失败时页面标明出错的任务段。

踏步线和箭头标出建筑模型中核对的三段楼梯与相邻平台，箭头指向图上写出的目的楼层。入口到下层的楼梯沿地图负 Y 方向上行，后两段沿正 Y 方向上行。连续的竖向结构用深色表示，较弱或孤立的回波用浅色表示。规划限制默认关闭。

下层平台可下行至入口、上行至中层。中层平台的两段楼梯平面投影重叠，图上并排显示两个方向及目的楼层。顶层尚无已标注的连接。

在楼梯内按住目标位置，沿期望朝向拖动后松开。落点只覆盖一段楼梯时，网页直接匹配该段的踏步。若落点覆盖多段楼梯，网页列出各段的连接楼层、踏步高度和可选状态。选择楼段即可保留原位置与朝向，取消本次选点会保留之前的草稿。两种操作同样适用于给定初始位姿。

重叠区域只要有一个楼段可作目标，规划限制图层就将该格显示为可选；各楼段的限制可在选点时分别查看。缺少匹配表面或规划受限的格子不能作为目标，路线连通性由规划器验证。

## 入口层地图重建与验证

本版本专用于仿真建筑 `Building`。生成器先用原始点云和 `SceneBuilding` 参数复算并比对原地图，然后筛选八邻域高度一致、净空足够的单格缺口。它用碰撞网格检查中心及周围点的地面支撑、垂直净空和侧向余量，通过之后才将估计的地面高度送入同一套 `PCT` 生成流程。原始点云、通行阈值和膨胀参数保持原值。

```bash
source tools/env_humble.sh
mkdir -p log/entry-map
CUPY_COMPILE_WITH_PTX=1 .venv-humble/bin/python tools/build_entry_map.py --report log/entry-map/repairs.json
cmake --install build/humble-pct/pct_planner
python3 tools/build_floor_display.py
cmake --build build/humble-bringup/legbot_bringup --target install
.venv-humble/bin/python tests/check_entry_map.py
```

`166` 个候选中有 `135` 个通过。入口层的可选目标栅格从 `9,469` 增至 `18,066`，净增 `85.97 m²`。逐格检查了全部新增格子中心的楼板支撑和至少 `0.50 m` 净空。其他四个显示层的选点掩模及返回的楼面高度逐格相同。目标是否能从当前位置到达仍需全局规划判定。

## 任务与状态接口

- `ROS 2 Action`（动作接口）`/navigation/follow_waypoints` 使用 `nav2_msgs/action/FollowWaypoints`。输入为有序 `PoseStamped[]`，坐标系为 `map`，高度为目标楼面高度。反馈 `current_waypoint` 从 `0` 计数。取消或失败时 `missed_waypoints` 包含当前未完成点及后续点。
- `/navigation/task_status` 保留最近一条任务状态。`index` 是已到达点数，`points` 存储有序地图坐标。一个时间只允许一个活动任务。刷新页面或断开浏览器不会停止机器人端任务。重启任务节点后需重新定位并下发。
- `POST /api/seed` 接收 `{floor,x,y,yaw}`。`POST /api/tasks` 接收 `{id,points:[{floor,x,y,yaw}]}`，每个网页目标都必须提供有限的偏航角，允许 `yaw=0`。`POST /api/cancel` 接收 `{id}`。`floor` 从 `0` 计数，`yaw` 为地图中的偏航角，单位为弧度。网页通过服务器发送事件（`SSE`）`/api/events` 接收状态快照，`GET /api/state` 可单独查询。
- 网页默认在距目标约 `6 cm` 时进入末端对齐。在同层、水平距离 `7 cm` 内、朝向误差 `4°` 内且连续 `0.6 s` 站稳后确认到达。末端转向需要局部碰撞检查许可。
- 局部规划连续失败时会缩短尝试的轨迹。已有全局路线且连续 `6 s` 没有位姿进展时，任务撤销运动许可、确认机身站稳，从当前位置对当前航点重新全局规划一次。重规划后仍持续 `20 s` 无进展则报错，保留剩余停靠点。取消、定位失效和无可用路线均进入停车流程。

## 仿真回归

在新启动、尚未定位、出生于默认入口的仿真中运行。该脚本实际下发运动指令，仅用于测试仿真。它检查定位后待命、单点、入口与下层连廊往返、第二点不可达、行走中取消和取消后新任务。传入 `--upper` 可把往返目的地改为上层平台。页面、`ROS 2` 服务和动作均由本机软件包提供，无需浏览器连接外部站点。

```bash
python3 tests/check_web_navigation_sim.py --url http://127.0.0.1:8765
```

加 `--entry-repair` 会再执行三个顺序目标，经过原先位于缺口中心的 `(-4.6453, 6.6132) m` 和 `(-5.4453, 7.2132) m` 后返回入口。

修补版已在 `Gazebo` 中完成上述三点任务、入口到下层平台往返、第二点不可达和取消后重发的回归。截图示例 `(2.15, -0.89) m` 现在有有效楼面且可选，但从默认入口 `(-5.5, 6.0) m` 离线调用同一 `PCT` 规划器时仍报告无全局路线。

本次 `Gazebo` 实测完成了入口附近单点、第二点不可达后保留第一点进度、行走中取消、取消后再次下发，以及入口与下层连廊往返。往返的两个目标分别是下层 `(0.25, -4.50) m` 和入口 `(-5.50, 6.00) m`。控制器两次均从新鲜里程计确认停车后才推进任务。测试通过网页使用的 HTTP 接口下发命令。界面拖箭头、跨层加点、调序、删除、取消和重新载入剩余点另做了 DOM 交互测试。

入口到上层 `(2.0, -3.0) m` 单程也已走通。较长的上层返程在不同轮次出现过局部规划停滞和地图位姿估计跳变。一次在停稳后从当前位置重新下发，成功返回入口。上位机现在会在机身估计离开地图边界时撤销任务，并要求重新定位。长程返程的稳定性仍需单独验证。这里的到点判断采用导航里程计，本次没有测量独立真值误差。
